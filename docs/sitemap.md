# 사이트 구조

주소·화면·API 전부. **코드에서 확인해 적었다** — 추측으로 채운 칸은 없다.

상태: **현행** (2026-08-04 기준)

관련 문서: [feature-scan.md](feature-scan.md) · [population-features.md](population-features.md)

---

## 1. 한눈에

```
/                          메인 — 조회 · 결과 · 안내문(SEO)
├── ?ids=a,b[,c,d]         비교 모드 (2~4명)          ← 전용 주소 없음
├── ?tab=<탭키>            열린 탭
└── ?pm=&mo=&yr=&sn=&st=&en=   기간 필터

/player/<식별코드>          단일 조회 — 메인과 같은 화면, 제목만 서버가 붙인다
└── ?tab= · 기간 파라미터 동일

/player/<식별코드>/report   한 장짜리 리포트 (서버 렌더)
├── ?season=S3 | ?from=&to=    범위
├── ?lang=ko|en|ja             표시 언어
└── opengraph-image            공유 카드 (사람마다 다르게 생성)

/admin                     관리자 (비밀번호 · noindex)

/api/...                   아래 4장
```

바깥으로 나가는 링크 셋 — 전부 같은 사람이 만든 다른 사이트다.

| 표기 | 주소 |
|---|---|
| 철권 티어 | `season-end-web.vercel.app/tekken-tier` |
| 잡기 풀기 | `season-end-web.vercel.app/throwBreak` |
| 철권8 영상모음 | `tekken8-tube.vercel.app` |

## 2. 색인 정책 — **색인되는 페이지는 `/` 하나뿐이다**

이게 이 사이트 구조에서 가장 눈에 띄는 사실이다.

| | 색인 | 근거 |
|---|---|---|
| `/` | **된다** | `sitemap.ts` 의 유일한 항목 |
| `/player/<id>` | 안 됨 | `robots: { index: false }` |
| `/player/<id>/report` | 안 됨 | 같음 |
| `/admin` | 안 됨 | `admin/layout.tsx` 가 noindex |
| `/api/*` | 안 됨 | `robots.ts` 의 `disallow` |

`robots.ts` 가 `/admin` 을 **일부러 안 적는다** — robots.txt 는 공개 파일이라
거기 적는 것 자체가 "관리자 페이지가 있다"는 안내가 되고, 막으면 크롤러가
noindex 지시를 볼 기회조차 없어진다. 지금 방식이 맞다.

**그래서 검색 유입은 전부 `/` 한 페이지가 받는다.** `SeoContent.tsx` 가
그 페이지에 안내문·FAQ 를 길게 싣고 있는 게 그 때문이다.

## 3. 화면

### 3-1. `/` · `/player/<식별코드>` — 결과 화면

둘은 **같은 컴포넌트**다. `/player/<id>` 는 리다이렉트하지 않고 제목·설명만
서버에서 붙인다(주소가 튀지 않게).

조회 결과는 **탭 16개**다. 묶음은 "이 표가 어떤 물음에 답하나" 기준이다.

| 묶음 | 탭 |
|---|---|
| 요약 | `flow` 흐름 |
| 내 캐릭터 | `total` 캐릭터 · `round` 라운드 |
| 상대 | `pivot` 상대 캐릭 · `strong` 강점 매치업 · `weak` 약점 매치업 · `round_opp` 라운드(상대 캐릭) · `vs_rating` 레이팅대 · `h2h` 상대전적 |
| 언제 | `time` 시간대 · `time_local` 시간대(현지) · `sessions` 세션 · `daily` 일별 |
| 변화 | `season` 시즌 · `rank` 승단 이력 · `trend` 레이팅 추이 |
| 원자료 | `matches` 전적 목록 |

- `time_local` 은 지역을 읽었을 때만 생긴다 (`lib/wavu/region.ts`).
- `round_opp` 는 라운드 탭 안의 **보기 전환**이라 탭 줄에 따로 안 뜬다.
  엑셀에는 시트로 나간다.
- 그래프가 있는 탭: `trend` · `daily` · `sessions` · `rank`.

**모드 둘**

| | 주소 | 대상 |
|---|---|---|
| 단일 | `/player/<식별코드>` | 1명 |
| 비교 | `/?ids=a,b,c,d` | **2~4명** |

### 3-2. `/player/<식별코드>/report` — 리포트

**서버 컴포넌트다.** 완성된 HTML 로 나가야 공유 링크·인쇄(PDF)·크롤러에
그대로 쓰인다. 클라이언트로 내려가는 건 추이 그래프의 점들뿐이다.

범위·언어를 쿼리스트링에 두는 것도 같은 이유다 — 클라이언트 상태로 만들면
리포트 전체가 클라이언트로 내려가 인쇄·공유가 다 깨진다.

절 순서:

```
secForm      최근 폼          secActivity  날짜별 활동
secTrend     레이팅 추이      secChars     캐릭터별
secMatchups  매치업           secSeasons   시즌
secWhen      시간대           secGap       레이팅대
secDetail    상세
```

세 언어(`ko` / `en` / `ja`)를 쿼리로 전환한다.

### 3-3. `/admin`

비밀번호 필수. Google Analytics 조회 기록을 보고 엑셀로 내려받는다. noindex.

## 4. API

**전부 `robots.ts` 에서 막혀 있다** (JSON 이라 meta 태그를 실을 수 없어서
막을 방법이 robots.txt 뿐이다).

| 주소 | 메서드 | 하는 일 |
|---|---|---|
| `/api/replays/<식별코드>` | GET | 집계 결과. `?start=&end=` |
| `/api/compare` | GET | 2명 이상 비교. `?ids=a,b,c&start=&end=` |
| `/api/search` | GET | 닉네임 검색 중계 → `[{id, name}]` |
| `/api/random` | GET | 볼 만한 플레이어 하나. `?region=ko` |
| `/api/xlsx/<식별코드>` | GET | 엑셀. `compare` 를 식별코드 자리에 넣으면 비교본 |
| `/api/visitors` | GET | 방문자 수. **공개** |
| `/api/probe` | GET | 배포 직후 자가진단 — 조용히 깨지는 것들을 한 번에 본다 |
| `/api/admin/stats` | POST | 관리자. 비밀번호 필수 |
| `/api/admin/xlsx` | POST | 관리자. 비밀번호 필수 |

상류는 하나다 — `wank.wavu.wiki/player/<식별코드>/replays`.
**요청은 한 번에 하나씩** (레이트리밋). 비교 모드도 순차 수집이다.

## 6. 앞으로 — 구조에서 실제로 빈 곳

**보류·폐기한 것들은 뺐다** (리더보드 · 인구 통계 · 글리프 · 퍼센타일 배지 ·
실시간 오버레이 · 과금). 스테이지·단 이름 반영도 뺀다 — 그건 이미 결정 대기 중이다.

아래는 **위 구조를 훑다가 나온 것들**이고, 전부 코드로 확인한 사실에 근거한다.

### ① 비교 결과에 주소가 없다 — **가장 큰 구멍**

비교는 2~4명을 나란히 놓는 **일급 기능인데** 전용 라우트가 없다.
`/?ids=a,b` 로 홈 화면의 쿼리 상태로만 존재한다. 결과가 이렇다:

```
실측 — https://tekkenstats.com/?ids=53deQ2dmLday,4J2HAybjN64n
  <title>  철권 전적 검색 — 철권8 랭크전 전적 통계 | Tekken 8 Stats
  og:image https://tekkenstats.com/opengraph-image.png      ← 사이트 공통 이미지
```

**누구와 누구를 비교한 링크인지 아무 데도 안 나온다.** 카톡·디스코드에 붙이면
그냥 사이트 홍보처럼 보인다. 비교는 원래 남에게 보여주려고 쓰는 기능인데
공유가 제일 안 되는 모양이다.

`/player/<id>/report/opengraph-image.tsx` 가 이미 그 문제를 이렇게 적어뒀다 —
"공통 이미지를 쓰면 누구 링크인지 알 수 없어 공유가 잘 안 퍼진다."
리포트는 풀었고 비교는 안 풀었다.

- 할 일: `/compare` 라우트 + `generateMetadata` + OG 카드
- 값: 높다. 이미 있는 기능의 전파력만 올린다
- 비용: 중간. 라우트 하나 + 카드 하나

### ② `/player/<식별코드>` 도 공통 카드를 쓴다

같은 문제의 작은 판이다. `openGraph` 에 `title`·`description` 은 있는데
**이미지가 없어서** 사이트 공통 이미지로 떨어진다.

정작 사람들이 주고받는 주소는 리포트보다 이쪽이다(조회하면 주소창이 이 주소가 된다).

- 할 일: `player/[id]/opengraph-image.tsx`. 리포트 카드를 거의 그대로 쓸 수 있다
- 값: 중간~높음
- 비용: **낮다.** 기존 카드 재사용

### ③ 색인 페이지가 `/` 하나뿐인 걸 그대로 둘 것인가

플레이어 페이지를 색인에서 뺀 건 맞는 판단이다(내용이 사람마다 다르고 무한히 늘어난다).
그런데 그 결과 **검색으로 들어올 문이 한 개**고, 그 한 페이지에
안내문·FAQ 를 다 밀어 넣고 있다.

이건 결함이 아니라 **선택**이다. 다만 지금은 그 선택을 한 기록이 없다.
검색 유입을 늘릴 생각이라면 `/guide/식별코드-찾기` 같은
**색인 가능한 설명 페이지**를 따로 두는 게 정공법이다.

- 할 일: 먼저 **판단**부터. 늘릴 건지 말 건지
- 값: 미지수 — GA 유입 데이터를 봐야 안다
- 비용: 판단은 0. 만들면 페이지당 중간

### ④ `/api/probe` 가 배포 확인의 유일한 창구다

이건 잘 만들어진 쪽이다. 다만 **사람이 직접 열어야** 한다.
지금은 푸시할 때마다 손으로 확인하고 있다.

- 할 일: 배포 후 자동 호출(GitHub Actions 또는 Vercel 배포 훅)
- 값: 중간. "조용히 깨지는 것"을 잡는 그물이 이미 있는데 당기는 사람이 필요할 뿐
- 비용: 낮다

### 정리

| | 값 | 비용 | 순서 |
|---|---|---|---|
| ② 플레이어 OG 카드 | 중~높 | **낮음** | **먼저** |
| ① 비교 전용 라우트 + 카드 | **높음** | 중간 | 다음 |
| ④ probe 자동 호출 | 중간 | 낮음 | 곁들여 |
| ③ 색인 정책 | 미지수 | 판단 0 | 데이터 보고 |

**②를 먼저 한다** — 가장 싸고, ①에 쓸 카드를 미리 만드는 셈이라 ①의 비용도 깎인다.
