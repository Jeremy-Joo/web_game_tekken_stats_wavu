# 랭크 포인트 복원 시도 — 만들었다가 뺐다 (2026-08-05)

wavu 데이터만으로 **랭크 포인트(단위 포인트)** 를 복원해 화면에 띄웠다가 하루 만에 되돌렸다.
같은 시도를 다시 하기 전에 이 문서를 먼저 읽을 것. 되돌린 커밋에 코드가 그대로 남아 있다.

> 후속: 이 문서의 실패 원인(자기검증)을 피해 **랭크 포인트 값 자체를 복원하지 않고
> `myRank`가 실제로 올랐는지만 직접 세는** 방식으로 다시 조사했다 —
> [rank-threshold-research.md](rank-threshold-research.md) (2026-08-07).

```
931c6dd  랭크 포인트 카드 추가
60f9094  모델 교체 (승점=패점)
<revert> 철회
```

## 왜 복원이 가능해 보였나

wavu 는 랭크 포인트를 주지 않는다. `/replays` JSON 24개 필드, `?_format=json`,
`/player/<id>` HTML(593KB) 전수 확인 — 어디에도 없다. `rating`(2,543 급)은 glicko2 라
완전히 다른 척도다(실제 랭크 포인트는 407,700 급).

그런데 **랭크 포인트는 0~999,999 연속값이고 단은 그 값의 구간일 뿐**이다.
그러니 단이 바뀐 경기 = 점수가 경계를 넘은 순간 = **정확한 기준점**이 된다.
wavu 는 모든 경기의 단을 주므로 기준점을 전부 알 수 있고, 남는 건 그 뒤 경기들의
증감뿐이다. 그 증감은 과거 세그먼트(전이와 전이 사이)로 적합할 수 있다.

**단은 캐릭터마다 따로다.** 섞으면 34단→36단 같은 도약이 생겨 기준점이 망가진다.

**승점과 패점을 따로 두면 안 된다.** 2파라미터로 적합하니 패점 > 승점인 단이 여럿

## 왜 뺐나

**검증이 자기검증이었다.** 36단 계수 220은 BASEBALL LOVE 실측(407,700)에서 역산한
값인데, 그 뒤 같은 계정으로 "오차 0"을 확인했다. 당연히 맞는다. **독립 표본으로
확인한 적이 한 번도 없다.** 화면에 나가는 숫자의 정확도를 사실상 모르는 상태였다.

곁가지 문제도 있었다.

- **모바일 레이아웃이 깨졌다.** 3열 그리드에 "약 275,000 P" 가 들어가면서 좁은 폭에서
  "약"과 숫자와 "P"가 각각 줄바꿈됐다.
- 표시 정책을 느슨하게 바꾸면서(구간을 벗어나도 경계로 당겨 표시) 숫자 표시율은
  46% → 82% 가 됐지만, **틀릴 수 있는 값을 더 많이 내보내는 방향**이기도 했다.

## 다시 하려면

1. **독립 검증부터.** 인게임에서 랭크 포인트를 확인할 수 있는 계정 5~10개로 오차를 재고,
   그 결과를 문서에 적은 다음에 화면에 붙일 것. 이 순서를 지키지 않아서 되돌렸다.
2. **저단(24단 미만) 데이터.** 표본이 고단 플레이어라 낮은 단은 세그먼트가 부족하다.
   일반 사용자는 대부분 여기에 있다.
3. **모바일 폭 먼저.** 숫자가 길어 3열이 안 들어간다. 2열이나 세로 배치가 필요하다.
4. 단 도약(기록 누락)이 캐릭터의 13.6% 에서 발생한다. 기준점을 어떻게 다룰지 정할 것.
