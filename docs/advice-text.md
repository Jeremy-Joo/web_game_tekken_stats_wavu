# 분석문이 고정 3줄이다 — 판정 갈래를 늘려야 하는 곳

농담은 428개인데 **권장 판수 설명문은 고정 3줄**이다.
이 문서는 그 격차와, 늘려야 할 것이 문장 수가 아니라 **판정 갈래**인 이유를 적는다.

## 2. 왜 농담보다 급한가

1. **끌 수 없다.** `showQuips` / `showCoach` 스위치 **바깥**에 있다 (`app/page.tsx:2317`).
   유머를 끈 사람도 이 문장은 본다.
2. **절대 안 바뀐다.** 농담은 `recordCount` 가 늘 때마다 한 칸씩 밀리지만, 이건 숫자만
   갈리고 문장 틀은 영원히 같다. 매일 오는 사람이 매일 같은 문장을 본다.
3. **이 사이트의 본체다.** 흐름 탭의 핵심 산출물인데 정작 제일 딱딱하다.

## 3. 접근법은 농담과 **반대**여야 한다

농담은 "같은 상태 = 다른 문장"이 목적이다. 분석문에 같은 방식(씨앗 기반 무작위 선택)을
쓰면 `app/jokes.ts` 머리말이 세운 원칙을 정면으로 어긴다:

> 조회 결과가 같은데 말이 달라지면 신뢰가 깎인다.

**늘려야 할 것은 문장 수가 아니라 판정 갈래다.**
지금은 데이터에 있는 정보를 두 갈래(꺾임 있음 / 없음)로 뭉개고 있다.

> **지켜야 할 선**: 숫자 하나에 문장 하나가 대응해야 한다.
> 같은 데이터에 두 문장이 후보로 남는 순간 씨앗을 쓰게 되고, 그때부터 분석문이 농담이 된다.

## 4. 늘릴 수 있는 갈래 7가지 — 전부 이미 계산돼 있다

| # | 갈래 | 지금 | 나올 수 있는 말 |
|---|---|---|---|
| 1 | **꺾이는 폭** | 3%p나 15%p나 같은 문장 | `4%p 정도라 오차에 가깝습니다` / `18%p 급락합니다. 명확한 한계선입니다` |
| 2 | **꺾이는 시점** | 숫자만 다름 | 10판째 → `짧게 자주가 맞습니다` / 45판째 → `체력은 좋은 편입니다` |
| 3 | **`goodUpTo`↔`stopAfter` 간격** | 안 씀 | 붙어 있으면 `딱 잘립니다` / 벌어져 있으면 `그 사이는 애매 구간입니다` |
| 4 | **첫 구간부터 나쁨** | `stopAfter=0` 도 같은 문장 | `세션 길이 문제가 아닙니다. 시작부터 안 풀리는 쪽입니다` |
| 5 | **`avgDelta`** | **어디서도 안 쓰임** | `31판째부터는 이겨도 레이팅이 안 오릅니다` |
| 6 | **표본 부족의 이유** | `adviceThin` 하나로 뭉갬 | 경기가 적은 것 vs 세션이 짧아 뒷구간이 빈 것 |
| 7 | **후반 반등(U자)** | 첫 꺾임에서 `break` — 버려짐 | `한 번 꺾였다가 30판대에 다시 올라옵니다. 워밍업이 두 번 필요한 유형이죠` |

### ⑤ `avgDelta` — 가장 아까운 것

`lib/tekken/advice.ts:130` 에서 구간별 경기당 레이팅 증감을 계산해 화면까지 내려보내는데,
**문장도 차트도 쓰지 않는다.** 소비처를 찾으면 타입 선언 세 곳뿐이다:

```
app/page.tsx:137        bands: { … avgDelta: number … }[]   ← 타입만
lib/tekken/advice.ts:33 avgDelta: number;                    ← 타입만
lib/tekken/advice.ts:130 avgDelta: b.games ? … : 0,          ← 계산만
```

승률만으로는 안 보이는 정보다. 약한 상대를 만나 이기면 **승률은 오르는데 레이팅은 제자리**다.
"이기긴 하는데 남는 게 없는 구간"은 지금 데이터로 바로 나온다.

### ⑥ `reliable` 이 정보를 실패로 처리한다

```ts
reliable: usable.length >= 3,     // advice.ts:191
```

500판을 했지만 **항상 10판씩만** 하는 사람은 뒷구간 표본이 없어 `reliable=false` 가 되고,
`adviceThin`("표본이 부족합니다")을 본다. 사실 표본이 부족한 게 아니라
**그 사람이 짧게 하는 사람**이라는 정보인데, 그걸 실패로 뭉개고 있다.

CLAUDE.md 의 원칙과도 어긋난다 — **'모름'을 '0'으로 바꿔 말하지 말 것.**
여기서는 반대로 '알고 있는 것'을 '모름'으로 말하고 있다.

구분 기준: `records.length` 는 충분한데 `usable.length < 3` 이면 후자다.

## 5. 설명문이 아예 없는 탭들 (별건)

비교 모드에는 탭별 한 줄이 있지만(`tabQuip`), 그 조건이 `mode !== 'compare'` 로 막혀 있어
**단독 모드에는 흐름 탭 말고 어떤 탭에도 설명문이 없다.** 표만 있다.

| 탭 | 이미 있는 값 | 붙일 수 있는 한 줄 |
|---|---|---|
| 약점 매치업 | `WEAK_MIN_GAMES=5` | `5전 20%는 아직 표본이 아닙니다. 기억에 의존할 단계죠` |
| 라운드 | 접전·셧아웃 비율 | `3:0 패배가 34%입니다. 매치업이 아니라 정보 부족 쪽입니다` |
| 시간대 | 시간대별 승률 | `새벽 2시 이후 승률이 11%p 낮습니다` |
| 세션 | 세션 길이 분포 | `평균 8판씩, 하루 두 번. 짧게 자주 하는 분입니다` |
| 상대 캐릭 | 상대 캐릭 분포 | `만난 상대의 22%가 한 캐릭입니다. 그 매치업만 파도 됩니다` |

판정 로직을 새로 짜야 해서 흐름 탭보다 비싸다. **4장을 끝낸 뒤에 별건으로 다룰 것.**

## 6. 우선순위

| 순서 | 작업 | 손대는 곳 | 비용 |

## 7. 회귀 테스트

분석문은 **틀려도 화면이 멀쩡한** 부류다(문장은 나오는데 내용이 데이터와 안 맞음).
CLAUDE.md 관례대로 `npm run check` 에 물릴 것. `scripts/check-advice.ts` 가 이미 있으니
거기에 갈래 판정 케이스를 더한다.

최소한 이건 봐야 한다:

| 합성 이력 | 기대 갈래 |
|---|---|
| 20판째 3%p 하락 | ① 완만 — `오차에 가깝습니다` 쪽 |
| 20판째 18%p 하락 | ① 급락 |
| 첫 구간부터 평균 이하 | ④ `시작부터` |
| 항상 10판씩, 총 500판 | ⑥ `짧게 하는 사람` (`표본 부족` 아님) |
| 승률 유지 + `avgDelta` 음수 구간 | ⑤ `이겨도 레이팅이 안 오릅니다` |
